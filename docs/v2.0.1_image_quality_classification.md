# v2.0.1 画像問題 教育的品質改善フェーズ（全面再評価）

方針転換：「既存の自作assetを守ることは目的ではない」「オープン素材で置換できるものは差し替え前提で全面再評価する」という新方針のもと、リポジトリ内の自作（SVG-PRO）・簡略模式図assetを全件棚卸しし、以下の3区分で再分類した。

- **A：直ちにオープン素材へ置換**（今回実施）
- **B：置換候補あり、比較のうえ採否決定**（今回検討し、不採用と判断したものを含む）
- **C：適切なオープン素材が見つからず暫定維持**（自作のまま。理由を明記）

判断基準は「自作より少しマシ」ではなく「教材として見せたい品質に達しているか」。探索順はServier Medical Art → AnatomyTOOL.org → Wikimedia Commons → OpenStax Anatomy and Physiology → 学術機関公開教材 → その他。CC BY / CC BY-SA / CC0 / Public Domainのみ採用対象とし、改変必須でNDのものは不採用。

> **必須採用条件（人間レビュー後に追加）**：画像品質・ライセンスに加えて、**「その画像からmarker targetを解剖学的に一意に識別できるか」**を必須条件とする。実例：`q040_airway_branching.webp`（Servier「Bronchial tree」）は主気管支・葉気管支・区域気管支の識別には問題なく使えるが、**肺胞が描かれていないため終末細気管支と呼吸細気管支を画像単体で区別できず**、Q040（呼吸細気管支を問う設問）に使うのは不適切と判明。同assetは主気管支等を問うQ077/Q152/Q153では引き続き使用し（分岐の位置関係で一意に識別できるため問題なし）、Q040のみ`q041_alveolar_sac.webp`（肺胞が個々の泡状構造として明瞭に描かれた既存asset）へ差し替えた。詳細は下記「Q040の修正」節を参照。

## Q040の修正（人間レビュー後の対応）

人間レビューにより、`q040_airway_branching.webp`（Servier「Bronchial tree」）自体は画像品質として採用可能だが、**Q040（「呼吸部の始まり」＝呼吸細気管支を問う設問）に使うのは不適切**という指摘を受けた。

**問題の内容**：呼吸細気管支は「壁の一部に肺胞が開口し始める」構造だが、`q040_airway_branching.webp`は気管〜末梢気管支の分岐パターンのみを描いた図で、**肺胞が一切描かれていない**。そのため画像上のどの分岐レベルが「終末細気管支」でどこからが「呼吸細気管支」かを、図から一意に判別する手段がなかった（marker位置は末端の細い枝という推測に基づいており、解剖学的な裏付けを欠いていた）。

**対応**：
1. Q040の問題文・正答・marker_targetを再確認 → 呼吸細気管支を問う設問のまま変更なしと判断（設問自体は妥当）。
2. Servier / AnatomyTOOL / Wikimedia Commons / OpenStax等でbronchiole〜respiratory bronchiole〜alveolar ductの識別が可能な画像を探索する前に、**既存asset内**を確認したところ、`q041_alveolar_sac.webp`（Servier「Alveolar anatomy」、既にAccept区分でCC BY 4.0採用済み）に解決策を発見した。この画像は気管支の壁に**個々の肺胞が単独で膨らみ始めている箇所**（まだ房状の肺胞嚢になる前の、孤立した1個の肺胞バッドが壁から突出している部分）を明瞭に描いており、これが「呼吸細気管支＝壁に肺胞が開口し始める構造」を視覚的に一意に示す実在のランドマークだった。
3. そのため新規のオープン素材探索は不要と判断し、Q040の`image.asset`を`q041_alveolar_sac.webp`へ変更、markerをその孤立肺胞バッド上（既存のQ041・Q154・Q308のmarkerとは異なる位置）に再設定した。あわせて問題文中の図参照表現を「気道分岐図の①」→「肺胞嚢周辺の模式図の③」に最小限修正（choices・answer・explanationは無変更）。
4. `q040_airway_branching.webp`自体は、主気管支（Q152）・葉気管支（Q153）・区域気管支（Q077）という**分岐の位置関係のみで一意に識別できる**設問には引き続き使用する（指示どおり）。

**今後の必須採用条件**：画像品質・ライセンスに加えて「その画像からmarker targetを解剖学的に一意に識別できるか」を、今後すべての画像差し替え・新規採用の判断基準に加える。

## circulation_circuit／q021_vessel_cross_sections の追加再評価（第2回・詳細探索）

上記の方針に加え「その画像からmarker targetを一意に識別できるか」を必須条件として、両assetについて改めてOPEN素材を深く探索した。結論から言うと、**circulation_circuit・q021_vessel_cross_sectionsとも今回は差し替え保留（現状維持）**。以下に経緯を記録する。

### circulation_circuit：最有力候補が見つかったが、ラベル除去がクリーンにできず不採用

**候補：OpenStax *Anatomy and Physiology 2e* Fig.19.4「Dual System of Human Circulation」**（AnatomyTOOL.org経由、`https://anatomytool.org/sites/default/files/16795-232.jpg`、**CC BY 4.0**、2287×2525px）。

この図は上段に心臓の詳細断面（4心腔・4弁・大血管を実写調で描出）、下段に「肺→心臓→上半身／下半身」の実際の二重ループ（体循環・肺循環が上下2つの輪として明確に分離され、肺毛細血管網・全身毛細血管網の質感まで描かれ、全ての血管に白抜き矢印で血流方向が明示されている）という構成で、本asset下段部分は**本アプリが求める「8の字」構造・右心系／左心系の区別・血流方向・肺と全身の区別**を実写品質で満たす、これまで見つけた中で最良の候補だった。

ただし、英語テキストラベル（Right atrium／Left ventricle等）が本文中央の心臓交差部を含む図全体に高密度で配置されており、除去を試みた結果：
- 左右マージンのラベル文字は、色選択的な閾値処理（背景の白地に対する低彩度画素の置換）で問題なく除去できた。
- しかし各ラベルのリーダー線は、テキストからかなり深く図の内部（毛細血管網の中、心腔の交差部分）まで伸びており、直線検出（Hough変換）や手動トレースで座標を特定して消去を試みたが、
  - 元画像がJPEG（ラスター、テキストレイヤーの分離不可）であること、
  - 毛細血管網の網目模様自体が直線検出アルゴリズムに大量の誤検出を生じさせること、
  - リーダー線が心腔交差部という**図の中で最も情報密度が高い箇所**に集中して交差していること、
  により、消去のたびに「消し残りの線」または「誤って塗りつぶした構造線」のいずれかが発生し、複数回の反復処理を行っても実用品質（教材として配布できる完成度）まで到達できなかった。

**判断**：素材そのものはCC BY 4.0で内容も最適だが、本アプリのパイプライン（トリミング・WebP変換等の軽微な改変は許容、大規模な手動レタッチは今回のスコープでは実用的な時間内に完了できないと判断）で安全に改変しきれなかったため、**採用を見送り、現行の自作circulation_circuit.svg（本フェーズ直前に矢印・4弁を追加済み）を維持**する。

その他、以下も再確認・再検討したが、いずれも不採用：
- Patrick J. Lynch「Heart circulation diagram.svg」（Wikimedia Commons、CC BY 2.5）：心臓単体の外観図で、肺・全身との接続や血流方向矢印が無く、要件を満たさない。
- 既存B区分の3候補（Slagter＝CC BY-NC-SA、Wikimedia学生作図、Lynch心臓断面図）は前回同様不採用。

### q021_vessel_cross_sections：現行のハイブリッド構成を再確認、変更なし

現行asset（Servier実写画像2枚＋自作毛細血管パネル1枚の合成）を、今回追加された必須条件（marker targetの一意識別性）に照らして再確認した：
- 動脈panel：厚い筋層・弾性線維が実写で明瞭。marker位置（弾性線維・平滑筋が豊富な領域）は一意に識別可能。
- 静脈panel：薄い壁・広い内腔に加え、**静脈弁（V字型の弁尖構造）が実写で視認できる**。marker位置は一意に識別可能。
- 毛細血管panel：内皮1層＋基底膜相当の極薄壁として設計されており、単なる無地の細管ではなく内皮細胞核を模した楕円と壁の質感を持つ。marker位置（毛細血管本体）は他パネルと空間的に完全分離しており一意に識別可能。

新規に、動脈・静脈・毛細血管を1枚で描いたWikimedia「Blood vessels-en.svg」（Kelvinsong作、CC BY-SA 3.0）を再検討したが、前回同様「ラベルがテキスト要素ではなくパスとして図形に融合しており安全に除去できない」という理由で不採用（変更なし）。**現行のハイブリッド構成を維持**する。
